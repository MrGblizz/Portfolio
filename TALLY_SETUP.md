# Activer le questionnaire B-01 avec Tally

**État actuel : lien Tally configuré** (`https://tally.so/r/2jAxyV`) dans `brief-b01.html`. Le vrai questionnaire a été créé par le propriétaire ; l'intégration locale est prête, mais la réception, les notifications et les informations de confidentialité restent à valider avant publication. Remettre `TALLY_FORM_URL = ''` désactive le chargement Tally et affiche l'état d'attente.

1. **Vérifier le formulaire créé dans son compte Tally.** Comparer ses pages à `TALLY_QUESTIONNAIRE.md` ; vérifier chaque question, option, champ obligatoire, progression et logique conditionnelle dans l'éditeur. Mettre à jour le formulaire après validation des textes et informations de confidentialité.
2. **Vérifier la réception.** Dans les paramètres du formulaire, activer les *Self email notifications* et vérifier l'adresse de réception **dans le compte Tally**. Adresse professionnelle prévue : **[À CONFIRMER PAR LE PROPRIÉTAIRE]** ; ne pas interpréter `^` comme `@` sans confirmation. Vérifier aussi les réponses dans l'onglet *Submissions*. Aucun SMTP ni mot de passe n'est nécessaire sur GitHub Pages.
3. **Lien public renseigné.** Dans l'onglet *Share* du formulaire publié, vérifier que *Copy link* correspond bien à `TALLY_FORM_URL` dans `brief-b01.html` : `https://tally.so/r/2jAxyV`. Le même lien est utilisé pour le bouton de secours « Ouvrir le questionnaire ».
4. **Comparer l'intégration officielle.** Dans *Share → Embed → Standard → Get the code*, copier et conserver le véritable code d'intégration de **votre** formulaire. La page construit l'URL `https://tally.so/embed/…` à partir du lien public et utilise le script officiel `https://tally.so/widgets/embed.js` avec `dynamicHeight=1`, `alignLeft=1`, `hideTitle=1`. Le fond transparent est désactivé pour préserver le contraste du thème actuel du formulaire Tally. Comparer avec le code proposé par Tally ; si des réglages d'intégration ont changé, adapter les options dans `brief-b01.html`. Ne pas copier une URL d'exemple issue d'une documentation à la place de son propre lien.
5. **Tester avant mise en ligne.** Ouvrir `brief-b01.html` en local via `python3 -m http.server 8000`, sur PC et téléphone. Contrôler la hauteur dynamique, l'absence de barre de défilement imbriquée gênante, la navigation clavier, les cinq pages et les champs requis. Bloquer volontairement le script tiers et vérifier que le lien direct reste utilisable. Sans scripts réseau ni connexion, Tally ne peut pas fonctionner : ne pas prétendre le contraire.
6. **Tester un vrai envoi.** Soumettre un dossier de test complet puis des cas incomplets (sans email ou sans description de mécanique), budget inconnu, montant renseigné puis masqué, pièce jointe autorisée et type interdit. Vérifier le message de confirmation **après envoi réussi**, la réception dans Tally **et** la notification dans la boîte de réception (y compris les spams). Ne pas considérer le canal actif avant ce test de bout en bout.
7. **Publier seulement après accord.** Vérifier confidentialité, durée de conservation à définir, moyen d'exercice des droits, politique de confidentialité et mentions légales applicables. Puis publier les fichiers statiques sur GitHub Pages sous `/Portfolio/`. La réception dépend du compte Tally ; la page du site ne fabrique aucun devis ni confirmation d'envoi.

**À corriger dans le formulaire actuel :** sur la première page, « Nom du projet (facultatif) » et « Public visé (facultatif) » portent l'astérisque et leurs champs sont techniquement obligatoires. Désactiver *Required* dans Tally pour ces deux champs, puis vérifier les autres champs facultatifs, avant le test de soumission.

**Charte graphique :** le CSS de `brief-b01.html` ne peut pas modifier l'intérieur de l'iframe Tally. Dans l'éditeur Tally, *Customize → Custom* permet gratuitement de régler fond, texte, boutons, accents et police : essayer `#171412` pour le fond, `#f5f0eb` pour le texte et `#f59e0b` pour les accents, puis vérifier le contraste des champs et boutons sur mobile. Garder l'embed sur fond non transparent tant que le thème interne reste clair. L'injection de CSS personnalisé dans Tally est une fonctionnalité **Pro**, non nécessaire ici ; aucun abonnement n'est requis pour l'intégration.

Sur l'offre gratuite, Tally documente actuellement **10 Mo par fichier** (à confirmer au paramétrage). Configurer des types de fichiers sûrs dans Tally ; ne pas promettre les fichiers 3D non testés. Les pièces jointes ne doivent pas être publiées : attention aux liens exportés vers des outils tiers, qui peuvent donner accès aux fichiers à quiconque possède ces liens. Ne pas ajouter d'abonnement, d'API ou de classement automatique pour cette V1.
